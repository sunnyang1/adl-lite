# ADL Lite 商业计划书：合理性评估、第一性原理重构与对抗性审查

**日期**：2026-07-21
**审查对象**：《ADL Lite 商业化路径与商业闭环设计：商业计划书基础研究报告》（2026-07-11，五章版）
**审查方法**：合理性审计 → 第一性原理拆解 → 对抗性红队审查 → 改进方案
**注**：本审查基于审查日仓库真实状态（含 2026-07-21 提交的 Phase 2 代码），已核对报告各项论断的时效性。

---

## 0. 总体判断（TL;DR）

原报告是一份**高于平均水平的市场研究文档**——来源多元、假设显性化、内部逻辑自洽；但它是一份**及格的"研究报告"，而不是一份及格的"商业计划书"**。它的核心结论（"能自我造血，24–30 个月转正"）建立在三层未验证假设的连乘之上，且存在四个硬伤：

1. **单位经济学证伪**：按报告自己引用的计量定价锚点（$0.005/千次调用），托管 SaaS 层需要 **每年 3,000 亿次 API 调用** 才能撑到 $1.5M ARR——计量层在数学上不可能承担造血任务，报告未做这笔账。
2. **SOM 是"市场份额百分比法"**，而非自下而上的客户数推导；且"达成中性 SOM 即越过盈亏线"是同义反复——SOM 是假设出来的，盈亏结论自然成立。
3. **第 0 年资金缺口缺失**：报告自称"自我造血"，但第 1 年 $0.85M–$2.25M 支出在任何收入到账之前就需要花出去，资金来源只字未提。
4. **需求侧证据为零**：全文没有一个客户访谈、意向书或设计伙伴；"稀缺品类"被默认为机会，而未审查其对立面——**稀缺可能等于没有需求**。

**改进后的核心判断**：ADL Lite 的技术资产真实且差异化，但商业闭环的正确起点不是"托管注册表 SaaS"，而是**把密码学溯源能力包装成受监管客户的"AI 审计证据包"，按被治理系统数/年收费**——先以服务化 pilot 验证付费意愿，再把验证过的证据格式产品化。原计划的 SaaS 计量层应降级为长期使用模式，而非收入支柱。

## 1. 合理性评估：哪些成立，哪些不成立

### 1.1 成立的部分（应予保留）

| 论断 | 评估 |
|------|------|
| 产品化断层识别（路线图 100% 学术向） | ✅ 准确，且是最有价值的发现 |
| 竞争四类分法（记忆层/可观测/KG 平台/MCP 注册表） | ✅ 结构清晰，"无人同时提供溯源+共识+治理闭环"的判断基本成立 |
| MIT 下 Open Core + SaaS + 订阅可行，无需改许可 | ✅ 正确 |
| 成本结构估算（$0.85M–$2.25M/年） | ✅ 量级合理，SOC2 成本有真实来源 |
| 企业采购周期 6–18 月的风险提示 | ✅ 诚实 |
| 多源并列呈现口径差异（KG 市场、AI 治理） | ✅ 方法论上比同类报告诚实 |

### 1.2 不成立或脆弱的部分

**① SAM ≈ 60–120 亿美元：假设连乘的伪精确。**
推导链是：Forrester 治理支出 × 30–40%（假设份额）、Agentic 平台 × 8–12%（假设占比）、溯源池 110–180 亿 × 50–70%（假设共现率）。三个假设全部无来源、且互相乘叠。诚实的表述应该是：**这个品类的 SAM 目前不可知，因为它还不存在**——"可审计能力注册表"作为独立预算科目在任何企业的 IT 预算里都还没有位置。这不是说市场不存在，而是说用自上而下百分比切分一个不存在的品类，给出的 $6–12B 区间没有决策价值。

**② SOM 的"捕获 0.05–1%"是市场份额法，不是客户数推导。**
自下而上看：中性 SOM $1.5M–$3.5M ARR，按报告自己的合规年费区间 $50k–$500k，意味着 **3 年内签下并留存 10–30 个受监管企业客户**，外加 SaaS 长尾。一个零用户基数、零品牌、5–8 人团队、销售周期 6–18 个月的项目，3 年 10–30 个企业客户是可能分布的右尾，不是"中性"。报告把右尾当中性，把不可能当保守。

**③ 单位经济学硬伤（本审查最重要的发现）。**
报告引用的计量锚点：$0.005/千次工具调用、$0.25/千事件。算账：$1.5M ARR ÷ $5/百万次调用 = **3,000 亿次调用/年**（约 10 亿次/天）。作为对照，报告引用整个 MCP 生态月下载 9,700 万次——即使每次下载对应每天 100 次调用，全生态日调用量与 10 亿次/天也差多个数量级。**结论：按量计量层在可见未来对 ARR 的贡献约等于零，收入必须全部来自合规订阅层。** 报告把四层飞轮并列呈现，掩盖了"只有一层能产生有意义的收入"这个事实。

**④ "自我造血"叙事掩盖了第 0 年资金需求。**
阶段一（0–6 月）要完成信任模型、持久化、合规构建、GTM 设计——这些都是成本，发生在第一笔收入之前至少 6–18 个月。极简配置下第 1 年 burn 也在 $0.5M–$1M。报告通篇没有"钱从哪来"：创始人自筹？天使？Grant？这不是细节遗漏，而是"自我造血"这个核心命题的前提缺失——**任何商业闭环都需要启动资本，区别在于主动设计还是被动发现。**

**⑤ 需求侧证据为零。**
330 行报告引用了 30+ 市场数据来源，但没有任何一条来自潜在客户：没有访谈、没有 LOI、没有 waitlist、没有设计伙伴。Gartner"40% 项目取消率"被解读为需求顺风，对抗性读法同样成立甚至更强：**如果 40% 的 agentic AI 项目活不到 2027 年底，那么"agent 审计工具"的买家池正在同步缩水**——审计预算跟着生产部署走，不跟着项目立项走。两种解读都没有数据支撑，这本身就说明需求侧是本案最大的未知，而报告把它当成了已知。

**⑥ 信任模型的产品含义被低估。**
报告把 N_min=1、自验证 0.99 当作"工程阻塞项"，修法是"阶段一修 DID/Sybil"。但更深层的问题是：**单一客户部署内，所有验证者都是同一个组织的 agent——多智能体共识在单租户内没有抗共谋价值**。哈希链证明的是"记录没被篡改"（完整性），不能证明"记录的内容是真的"（预言机问题）。企业审计要的是后者。这意味着真正的产品差异化必须是**跨组织验证者联邦**（由审计方/行业协会运营独立锚定节点），这是一个比"修 N_min"大一个数量级的产品决策，报告完全没有触及。

### 1.3 时效性核对（报告写成后仓库发生的变化）

报告日期 2026-07-11；以下阻塞项**已经部分或全部解决**（2026-07-21 提交，审查日已验证）：

| 报告所列阻塞项 | 当前状态 |
|------|------|
| 信任模型弱（自验证 0.99、无 Sybil 抵抗） | 🟡 **部分解决**：`trust_model.py` 已落地——自我验证循环阻断、身份合并键、Sybil 过滤、dev/prod 双模式；但 `min_distinct_validators` 默认值仍为 1，跨组织联邦未开始 |
| pygit2 依赖未声明 | ✅ 已解决（`[experiments]` extra 已声明 pygit2+prov，懒加载优雅降级） |
| Neo4j 仅停留在 PRD | 🟡 **部分解决**：`neo4j_adapter.py` + `graph_backends.py` 已实现可插拔后端，CLI 支持优雅降级；但 NetworkX 内存图仍是默认 |

## 2. 第一性原理重构：把计划拆到原子，再重新组装

### 2.1 拆到原子（不可再分的、无需假设的事实）

- **A1**：受监管行业（金融/医疗）正在把 LLM agent 放进真实业务流程，且这个趋势不依赖 ADL 存在。
- **A2**：EU AI Act（Regulation 2024/1689）对高风险系统要求记录保存（Art. 12）、透明与可追溯（Art. 13）、日志可被监管机构调取；罚则真实存在。这些条款**不依赖任何市场研究机构的 TAM 预测**。
- **A3**：审计证据要可信，必须满足两个条件：完整性（没被改过）和真实性（记录的是事实）。密码学哈希链只解决完整性。
- **A4**：企业为"通过审计"付的钱，锚定的是**不通过的代价**（罚则、业务停摆）和**手工合规的成本**（咨询费、人力），而不是"每次 API 调用的价格"。
- **A5**：开源基础设施的商业化历史表明，收入集中于"托管 + 企业合规/支持"两层，纯计量层只有在巨量规模下才有意义（A4 的推论，且被 1.2③ 的算术证实）。
- **A6**：任何产品的早期收入来自**具体买家为具体问题付的具体钱**，不来自 TAM 的百分比。

### 2.2 从原子重建

**买家是谁？** 不是开发者（他们是用户），是**金融机构的模型风险/合规负责人**——他们的 KPI 是"通过监管检查"和"不被罚款"。开发者是冠军（champion），不是买家。原报告的获客模型把两个漏斗混成了一个。

**买家购买的原子单元是什么？** 不是"注册表"，是**"一份能交给监管/内审的、防篡改的 AI 系统行为与能力证据包"**。注册表是证据包的生产工具，不是产品本身。按 A4，定价单位应是 **"被治理的 AI 系统数/年"**，锚定手工合规成本（一次 AI 审计的咨询+人力成本通常在 $100k–$500k 量级），而不是每次调用 $0.005。

**最小可收费产品（MVPP）是什么？** 从 A1+A2+A3 出发：**ADL 证据流水线**——接入客户 agent 系统 → EventChain 记录能力/行为事件 → Merkle 锚定 → 一键导出符合 AI Act Art. 12/13 的证据包（含 PROV-O/OWL 互操作格式）。这恰好是 ADL 现有资产的最小组装，不需要先建多租户 SaaS。

**护城河在原子层面是什么？** 不是密码学（哈希链一个周末可以重写），而是三样慢变量：① **证据格式成为标准**（AO 论文 + W3C/PROV-O 对齐是标准制定的入场券——论文在这里不是学术负担，是 GTM 资产）；② **审计方侧的格式网络效应**（审计师学会读 ADL 格式后，客户被迫采用）；③ **跨组织锚定联邦的运营关系**（A3 的真实性一半只能靠独立锚定节点解决，运营关系不可复制）。

### 2.3 重构后的闭环（对比原四层飞轮）

| | 原报告 | 第一性原理重构 |
|---|---|---|
| 收入支柱 | 四层并列（核心层是按量 SaaS） | **合规证据订阅（按系统/年 $25k–$150k）为唯一支柱**；计量层降级为用量限制器 |
| 冷启动 | 开源社区 → 标杆 → 抽成 | **服务化 pilot 先行**：3–5 个设计伙伴付费 pilot（$20k–$50k/个），用 pilot 验证付费意愿并打磨证据格式 |
| 信任模型 | 工程阻塞项（修 N_min） | **产品本身**：跨组织验证者联邦，由审计方运营锚定节点——把 N_min 从配置项变成网络 |
| 论文 | 与商业化争夺资源 | GTM 资产：标准制定的入场券 + 合规叙事的权威背书 |
| 市场依据 | TAM/SAM/SOM 百分比 | 自下而上：10–30 个 EU 高风险场景（Annex III：信贷、保险定价、招聘）金融机构清单，逐个打 |

## 3. 对抗性审查：红队攻击原计划的七个击穿点

**攻击 1 — 品类不存在风险（致命级）。** "可审计能力注册表"今天没有预算科目。稀缺品类的对立面不是"蓝海"，是"买方不知道该把这笔钱记在哪个科目下，所以不花"。原报告没有任何证据表明买方已经为"能力级溯源"单独付过钱。**反方胜 unless 有付费 pilot 证据。**

**攻击 2 — 巨头吸收（高危）。** 报告自己引用的 AWS Bedrock AgentCore 已经在做 agent 网关+记忆+计量，Microsoft 在 MCP 层要求代码签名，GitHub 在运营注册表。这些玩家缺的不是技术，是一个"足够大的合规事件"来触发它们把溯源内建。"我们是开源+标准"不是防御——**开源和标准恰恰降低了被吸收的成本**（它们可以直接实现 ADL 的格式而不收购 ADL）。唯一有效防御是攻击 1 的反面：在巨头动手前让审计方生态锁定 ADL 证据格式。

**攻击 3 — 预言机问题（技术致命级）。** 哈希链 + DID 签名证明"这条记录没被篡改"，不证明"agent 当时确实做了这件事"。一个恶意或出错的 agent 可以把假行为签进链里，整条链密码学上完美、事实上虚假。监管审计问的是后者。原报告把"防篡改"当作"可审计"的充分条件，这是技术叙事对合规现实的偷换。**没有运行时行为证明（execution attestation）层的溯源，在严肃审计场景会被击穿。**

**攻击 4 — 单租户共谋（架构级）。** 见 1.2⑥：单组织内所有验证者同属一个信任域，N_min≥2 无意义。合规场景天然要求"独立于被审计方的验证"，这把产品从"软件包"推向"联邦网络"——成本、治理、冷启动难度全部上一个台阶。原计划的阶段一预算（6 个月）不可能完成。

**攻击 5 — 时间线内部矛盾。** 企业销售周期 6–18 月（报告自引），阶段二（6–18 月）要"签下 1–2 个受监管标杆"——意味着第 6 个月就要有已经进入采购流程的合格线索，即 GTM 必须在第 0 天就启动且创始人亲自卖。同时阶段一还要完成信任模型+持久化+合规构建的工程工作。**同一个人在同一 6 个月里既写 Coq 证明又跑银行采购流程——资源约束没有建模。**

**攻击 6 — 逆选择风险。** 最愿意早期买"agent 审计"的客户，往往是已经知道自己有合规问题的客户。这会带来定制需求地狱（每个 pilot 都是定制审计项目），拖垮 5–8 人团队的产品化节奏。需要明确的 pilot 边界条款（固定证据格式、不做定制集成）。

**攻击 7 — 中国市场缺位。** 报告的市场数据全部来自欧美机构，引用的唯一中文来源是招投标和 HiMarket 新闻。如果团队和客户关系在中国（从仓库协作者推断很可能），那么 EU AI Act 叙事与中国《生成式 AI 服务管理暂行办法》/算法备案制度的合规路径完全不同，**整份报告的市场测算可能在一个错误的地理市场里算了半天账**。这是框架级盲区。

## 4. 改进方案：修订版商业化路线

### 4.1 重新排序的四阶段（替代原三阶段）

**阶段 0（0–3 月）· 需求验证，不是工程**
- 访谈 15–20 个目标买家（金融机构模型风险/合规负责人、AI 治理顾问），核心问题只有一个："为一份能通过 AI Act/内审的 agent 行为证据包，你今年愿意付多少钱？"
- 同步确认地理市场：EU 叙事 vs 中国合规路径，二选一并写明理由。
- **通过/否决门槛**：≥3 家愿意签付费 pilot（$20k+）→ 继续；否则转向"把溯源 SDK 卖给可观测性 incumbent（Langfuse/Datadog 类）"的 B 计划。
- 成本：≈$0（创始人时间）。这是全案性价比最高的 3 个月。

**阶段 1（3–9 月）· 证据流水线 + 付费 pilot**
- 产品：ADL 证据包 MVP（接入 → EventChain → Merkle 锚定 → AI Act Art. 12/13 证据导出），不含多租户 SaaS。
- 工程收尾：信任模型生产化（N_min 默认≥2）、Neo4j/PostgreSQL 默认持久化——注：**此两项已完成大半**（见 1.3）。
- 签 3–5 个付费 pilot（$20k–$50k/个），明确反定制条款。
- 目标收入：$60k–$250k（验证信号，不是造血）。

**阶段 2（9–24 月）· 产品化 + 合规订阅**
- 把 pilot 沉淀的证据格式产品化："被治理系统数/年"订阅（$25k–$150k/系统/年）。
- 启动 SOC2 Type II；以论文+PROV-O/OWL 对齐推动证据格式进入行业标准讨论。
- 设计跨组织锚定联邦的最小形态（2–3 个独立锚定节点，可由审计合作方运营）。
- 资金：在阶段 1 有付费 pilot 证据后启动 pre-seed（$1M–$1.5M），或申请合规科技类 grant。**"自我造血"的定义修正为：18–24 个月内达到月收入覆盖当月运营成本，而非从第 0 天无外部资金。**

**阶段 3（24–48 月）· 联邦网络 + 规模化**
- 锚定联邦网络效应启动后，再评估托管 SaaS 计量层与市场抽成——此时如有真实用量，单位经济学才可能成立。

### 4.2 关键修正对照表

| 项目 | 原报告 | 改进方案 |
|------|--------|----------|
| 收入支柱 | 按量计量 SaaS（数学上不可能） | 按系统/年合规订阅 |
| 定价锚点 | AWS 每次调用价格 | 手工合规成本（$100k–$500k/次审计） |
| 首个产品 | 多租户托管注册表 | 单租户证据包流水线 |
| 信任模型 | 6 个月工程修复 | 产品核心：跨组织锚定联邦（分阶段） |
| 资金来源 | 未提 | 阶段 0 零成本验证 → 阶段 1 pilot 收入 → 阶段 2 pre-seed/grant |
| 需求证据 | 无（纯桌面研究） | 阶段 0 访谈 + 付费 pilot 作为硬性通过门槛 |
| 地理市场 | 隐含欧美，未申明 | 阶段 0 明确二选一 |
| 论文角色 | 资源竞争者 | 标准制定入场券（GTM 资产） |
| 失败预案 | 无 | B 计划：卖给可观测性/治理平台 incumbent |

### 4.3 证伪 KPI（每季度核对，触发即转向）

1. **Q1**：付费 pilot 签约数 < 3 → 品类假设存疑，激活 B 计划评估。
2. **Q2–Q3**：pilot 续约/转订阅率 < 50% → 证据包价值未成立，回炉产品。
3. **Q4**：订阅管线 < $500k ARR run-rate → 24 月造血目标不可达，下调团队 burn 而非加注。
4. **任意时点**：若 AWS/Microsoft 在 MCP Registry 内建能力级治理 → 立即转向"成为其溯源格式供应商"策略，不再正面竞争。

## 5. 结语

原报告的技术资产盘点和竞争分析是扎实的，值得保留；它的失败在于把"市场研究"误当作"商业计划"——用别人的 TAM 数字代替自己的客户证据，用四层飞轮的完整性掩盖单位经济学的不成立，用"自我造血"的叙事回避启动资金问题。

第一性原理给出的答案更朴素：**有人会为"通过审计"付钱；ADL 能把通过审计所需证据的成本降一个数量级；从这句话到收入之间的最短路径是付费 pilot，不是 SaaS 平台。** 先证明有人付钱，再建设收钱的基础设施。
